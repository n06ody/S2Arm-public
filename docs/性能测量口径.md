## 纯工作量类的小效应用同局交替，不用分局对照（11-12）

量「开一个开关省不省 GPU / CPU 时间」时，效应在 1 ms 级就不要分局比：机身热起来后 GPU 降频，同一配置连跑两局，每帧 GPU 中位能差 4 ms、整机差 1 W 以上（11-12 实测：同包同开关两局 13.19 / 17.32 ms），局间波动把效应盖掉。

做法：被测开关做成按出图次数分段交替（偶数段关、奇数段开，例如每 120 次出图换一次），一局里采 200 秒左右，拿相邻的「关、开」两段凑一对：

- 每段丢掉首尾各 15 帧（切换瞬间与在途提交），取段内每帧 GPU 时间的中位数；
- 报成对差的中位数、均值，以及「开更低」的对数 / 总对数；
- 同时报两臂每帧绘制笔数的中位数：差得多说明自动玩家路线让场景对不上，这局不算；
- `frames.tsv` 第 n 行的 `gpu_us` 是第 n − 1 帧的，分段时按「帧号 − 1」算段号。

这样两臂在同一局、同一热状态、相邻场景里，局间波动成对抵消。11-12 一例：38 对，成对差中位 −0.65 ms（−4.1%），27 / 38 对开更低；而同一改动分局跑四局分不出方向。

整机功率、帧率这类大效应（差 1 W、差 10 帧以上）仍可分局比，但要写明每局的热状态，电量 100% 且不在充电（账本「充满」）才进定量。交替开关属于被测改动本身，不算重探针；带它的局写明「同局交替」。

## 功率、调度、频率、刷新节拍类改动：热机稳态整局对照（11-12）

改动只要会影响功率、线程调度（调度档、实时声明、亲和）、核心频率或刷新节拍，而不只是改每帧工作量，入车前就按整局量，不用同局交替：

- 同机、同场景，先把机器跑热到稳态（连跑一两局，直到帧率与整机功率不再逐窗口变化），再开始计数；
- 开、关各至少两局，交错排（关、开、关、开），每局写明热状态与供电；
- 判据是帧率和整机功率，同时报进程 CPU 功率、性能核用量；有动态分辨率的游戏再报主遍分辨率。

为什么不用同局交替：手机稳态整机功率是定的，CPU 多花的功率由系统从 GPU 上扣回去，这个过程有几十秒的时间常数，比交替的段长得多，交替量出来的方向可以是反的。11-12 一例：提交线程实时声明用同局交替量出帧率 +12% / +20% 后合入；当晚热机整局对照，开 30–39 帧、进程 CPU 0.57–0.76 W，关 42–47 帧、0.34–0.45 W，随即撤回。

有动态分辨率的游戏还有一层：省下的 GPU 时间会被游戏拿去升分辨率，每帧 GPU 时间看不出变化。量这类游戏时，尺子是帧率加主遍分辨率（`DM_NVN_GPUPROF` 取 100 帧看主遍尺寸），不单看 GPU 时间。

## 报告写法

读数后面写局的口径：「测量局」或「诊断局（开了什么）」。跨口径不比；旧口径读数要引用就标「旧口径，可能偏低」。

### 安卓直连图形队列的 GPU 空闲账

在启动游戏前设置 `debug.s2a.nvk_gpu_idle=1`（缺省 0）。计分外的一局进入可操控野外场景，在相同路线取连续的 `GPU 空闲账` 行。该开关可以独立于 `nvk_gputime` 使用。每完成约 5 秒的采样输出一行，`dt_s` 为实际墙钟窗口。

- `intra`、`inter` 分别给出帧内、紧跟呈现提交后的相邻提交对数 / 空档毫秒总和。区间从前一提交的 GPU BOTTOM 到下一提交的 TOP；有前置命令缓冲时从其开头计。渲染到呈现这一对归帧内。流水重叠记 `overlap`，该对贡献 0 毫秒。各项毫秒数除以同窗 `frames` 得每帧估值，`frames` 是已完成的呈现提交数。
- `bits` 是图形队列的有效计数器位数，`cal_ext` 表示已启用校准时间戳扩展。只比较本队列的设备时间戳，不跨设备时钟。硬件可在所请求流水阶段之后写时间戳；空档是所测图形队列的估计，不能据此推出整片 GPU 空闲。无校准扩展时跨提交时间戳的可比性还依赖驱动。
- `samples` 为有效提交数，`missing` 表示缺时间戳或跳过的提交，`ambiguous` 表示超出半个计数器周期等无法确定的样本。缺样切断相邻关系；`bits=0` 或无有效样本的窗口不能作为空档为零的证据。
- `cpu_wait_count/ms` 按调用位置统计等待次数 / 毫秒总和。包括 QueueFinish、SyncWait、读纹理前序及复制、复用呈现槽位和排空交换链的等待。仅统计进入条件变量等待的调用，后台完成线程的常驻栅栏等待排除在外。`submit_call` 单列队列提交调用的墙钟开销（含录制队列排空），不能与设备空档相加。等待和提交耗时按观测完成时入桶。

- 同窗的 `GPU 映射读账` 与主行共用 `end_mono_ns`。`reg/view/resolve` 给出注册、取纹理视图、解析底层纹理在资源锁上遇忙的次数与等待毫秒。等锁期间线程可能被调度走。`land` 和 `ReadTexels` 各按实际源分配的 `HOST_CACHED` 位分列次数 / 有效字节 / CPU 拷贝毫秒，无法识别的源单列 `unknown`。行距填充不计，等 fence 的时间留在主行。`bc_gpu_record_count/bytes` 是录制的 BC 压缩影子拷贝，后续 CPU 真读时按最终调用点归账。帧日志读取普通主存环。两处的映射读均标 NA。
- 在同一个计分外野外长局，每 60 秒和正常退出资源拆除前取 `管线常驻`。安卓 `ts_ns` 用 CLOCK_BOOTTIME，宿主时钟见 `clock`。`graphics` 为图形管线数，`compute` 为缓存及未缓存但仍驻留的计算管线数；两者只含 NVN 回放管线。`warm_built` 为本局预热新建并装入的图形与计算管线对象总数，同配方的命中不增加。`VmRSS_kB` 和 `maps` 来自同一进程的 status 和 maps，读不到记 −1。以同一 PID、同一 BOOTTIME 将每五分钟的采样与执行器的 PSS、malloc、热状态、尾窗帧率配对。异常杀进程时以最后一条周期样本为准。

# 贡献者开发测试套件：四步闭环

给手里有自己游戏和设备、想帮 S2Arm 测试或修问题的外部贡献者，包括 AI 贡献者。按下面四步走，**不需要维护方的机器、路径或密钥**：

1. **自查**：一条命令，用你自己的游戏出包、起局，自动出一份标准化报告。
2. **自纠**：按报告里的症状翻对应的排查手册，定位根因。
3. **自修**：让你的 AI 加载仓库里的 skill，按「先红后绿、负对照、报射程」修机制。
4. **提 PR 与回报**：按模板交读数；你的报告可以直接成为能力卡的验证证据。

文中 `<你的游戏>`、`<款>`、`<程序号>` 都是占位：`<款>` 是一键出包给这款游戏起的短名（见第 2 节），`<程序号>` 是游戏的 16 位十六进制 Title ID。领任务、分支、安全规矩见 协作循环 和 [贡献指南](贡献指南.md)。

**游戏和密钥一律自备**：我们不提供、也不接收任何游戏文件、密钥、存档、资源包或游戏截图。仓库、PR、评论里都不许出现这些。

## 第 1 步 自查：一条命令出标准化报告

```sh
bash tools/doctor.sh                                    # 先查环境，缺什么按提示补（只读，不装不改）
S2A_WIDEN_AUTO_RUN=0 bash pack/oneclick/oneclick.sh '<你的游戏目录>' --target mac   # 出 Mac 能跑的私有产物根（第 2 节），首次约 40 分钟
S2A_CS=1 S2A_IN='<输出>/roots/<款>@现行' bash runtime/run_mac.sh '<款>' '<局目录>' 280   # 起一局 280 秒（第 3 节；用自己的 iPhone 见 3.3，S2A_DEVICE_OWN=1）
export OPENROUTER_API_KEY=<你自己的钥匙>                # 或 ANTHROPIC_API_KEY；都没有时装好并登录 claude 命令行，自动用你自己的 Claude 看图
python3 tools/quality_check.py '<局目录>' --report '<报告目录>' --game '<款>' --device '<机型>' --contributor '<你的 GitHub ID>'
```

- **报告里有什么**：`<报告目录>/report.md` 是移植质量快检五项（画面 / 帧率 / 满屏 / 直连默认启动 / 能耗）的结论表、读数和证据清单，整段贴进 issue；`report.json`（格式 `s2a.quality-report.v1`）写工具指纹、判官、程序号 / 构建号、每份证据的 sha256 和报告指纹；`evidence/` 是判定用到的截图、`frames.tsv`、`gfx_mode.txt`、功耗采样、`host.log`。结论由工具判，不靠人看；本机路径、用户名、设备号、邮箱、IP、钥匙样字符串自动脱敏。
- **Mac 局**没有功耗和 iOS 屏比，满屏、能耗两项记「没数据」；三种判官钥匙都没有时，画面、直连默认启动两项记「没数据」，其余照判。也可以用 `S2A_QC_PROVIDER=openrouter|anthropic|claude-cli` 指定判官。
- **局目录要有哪些文件**：Mac 局和 iPhone 局都认，工具自己判；iPhone 按 3.3 手动起局时，局目录顶层至少要拉回 `host.log`、`frames.tsv`、`shots_ap/ap_*.png`，想判能耗再按 5.2a 采两次 `pwh.plist` / `pw1.plist`。完整清单和报告字段见 [5.2a](#52a-一条命令自查移植质量快检报告可直接贴-issue可入能力卡)。
- **自己复核**：`python3 tools/caps_ledger.py verify '<报告目录>'` 复算证据 sha256 和报告指纹，提交前跑一遍。
- **想看单款三率**（解包 / 进局 / 0 崩）：`bash tools/census/census.sh '<批次目录>' --type 实验 --src '<游戏源目录>' --hosts local`，全流程只在本机。
- 出包见第 2 节，起局见第 3 节，各项读数怎么看见第 4 节；单款快测和精修工具见 [快速测试与精修流程](快速测试与精修流程.md)。

| 没走直连、退回通用、直连异常 | [直连异常与退回通用](排查/直连异常与退回通用.md) |

## 第 4 步 提 PR 与回报

- **提 PR**：先跑 `bash tools/contrib_check.sh`（第 5 节），摘要原样贴进 PR。按 [PR 模板](../.github/pull_request_template.md) 填四栏：修前 → 修后读数、负对照、射程、一级自检。
- **报问题**：只玩不修的玩家用「问题回报」模板，附 App 导出的诊断包。贡献者用「自查报告」模板，贴第 1 步的 `report.md`、附 `report.json` 和去掉截图的 `evidence/`（公开仓不收游戏画面，截图留在你本机，维护方要抽查时单独找你）。两种都由工具生成、自动脱敏，不用手抄日志。
- **你的报告会成为证据**：贡献者自查报告按以下规则进能力卡：
  - 工具生成、原始产物齐（`frames.tsv`、功耗、`host.log` 随报告交；截图留在你本机，只交指纹）、指纹能复算的报告，记为「贡献者验证」；
  - 同一「游戏构建号 × 设备型号」有 2 份独立报告结论一致，或 1 份报告加维护方抽查原始产物通过，升为「已验证」；
  - 两份报告结论相反时两份都记「冲突」，由维护方看原始产物裁定；同一署名重复交不算独立；
  - 工具版本落后于 main 上判据改动的报告不收。
- **真机读数绑在你的产物上**：PR 里写明合流基点（`git merge-base HEAD origin/main`）和 APK / IPA 的 SHA-256。main 之后再往前走，你的验收读数照样有效，不用追着重测。只有一种情况要重验：基点到当前 main 的增量（`git diff --stat <基点>..origin/main`）动到了你改的同一目录或同一模块。规则见 协作循环 第 4 节第 5 条。
- **不同 iPhone / Mac 型号的覆盖**，主要靠贡献者补；领卡见 协作循环。

## 1. 环境

### 1.1 一条命令查缺什么

```sh
bash tools/doctor.sh          # macOS 自带的 /bin/bash 是 3.2；没装 Homebrew bash 时 doctor 会直接报「bash 5」缺
```

只读，不装、不改、不下载。每项一行，格式是「✅ / ❌ 名称：本机读数（要求，来源）」；缺的项下面多一行 `→ <能照做的安装命令>`，末尾每个缺项再打一行 `缺：<名称>`。退出码 0 = 全齐，1 = 有缺项。全齐时的真实输出：

```text
✅ bash 5：5.2.37(1)-release（要求 ≥ 5，门禁 / 列车按 Homebrew bash 写和测）
✅ Python 3.12+：python3 = 3.14.7（/opt/homebrew/bin/python3）
✅ Python 包：tools/rewriter-requirements.txt 全部对上（<你的 venv>/bin/python3）
✅ Xcode：<你装的版本> + iOS SDK（不限定版本，按本机 xcode-select / 启动器配置解析）
✅ .NET 10 SDK：dotnet SDK 10.0.403（/Users/<你>/.dotnet/dotnet；要求 10.0.403、rollForward latestFeature，compat/tree/global.json）
✅ 改写器固定依赖：<目录>（Capstone 5.0.7 / LZ4 4.4.5，runtime/rewriter/README.md）
ℹ️ 部署目标：MACOSX_DEPLOYMENT_TARGET=15.0 IPHONEOS_DEPLOYMENT_TARGET=18.0 （tools/toolchain.env，构建脚本自动带）
```

**第一次多半会报缺「改写器固定依赖」**：照它给的提示联网下载一次即可，`python3 runtime/rewriter/prepare_deps.py build/rewriter-deps`（钉版源码，下完不再联网）。不想联网时可以设 `S2A_REWRITER=python` 走纯 Python 改写器，结果相同但慢得多。

doctor 查的是「开发 / 跑门禁」要的工具。只想出包的话，另有一个出包专用的检查（判据和 Mac 前端的环境检查同一份）：

```sh
python3 pack/jobs/applenv.py              # 只读：每项一行 🟢/缺，括号里写这一项是「打包」「启动」还是「只单测要」
python3 pack/jobs/applenv.py --install dotnet   # 显式安装 .NET 10 SDK 到 ~/.dotnet（不要管理员密码）
```

### 1.2 各领域最低要求

| 领域 | 要求 | 出处 |
|---|---|---|
| Mac 芯片 | 开发、跑门禁、在 Mac 上起局：Apple 芯片（M1 及以后），游戏原生执行要 arm64。Intel Mac 只能给 iPhone 出包（见 2.4） | `docs/内测教程.md` 第一节；`tools/contrib_check.sh` 头注释写的是「自己的 Apple Silicon Mac」 |
| macOS | 在 Mac 上起游戏：macOS 26 或更新。产物最低系统版本 `MACOSX_DEPLOYMENT_TARGET=15.0` 是编译下限，不等于游戏能在 15 上跑 | `docs/内测教程.md`；`tools/toolchain.env` |
| Xcode | 用本机已安装的 Xcode，不限定固定版本：出包入口先用启动器 / 本机配置的 `S2A_DEVELOPER_DIR`，再选已安装的最新 Xcode，找不到时才用 `xcode-select`。需指定某套 Xcode 时设置 `S2A_DEVELOPER_DIR=<Xcode.app>/Contents/Developer`。装完打开一次、同意许可并安装 iOS 平台与 Metal Toolchain；仍须通过 SDK 下限和 Metal 能力检查 | `tools/toolchain.sh`；`tools/doctor.sh`；部署目标见 `tools/toolchain.env` |
| .NET | .NET SDK 10.0.403，`rollForward latestFeature`（10.0.4xx 及更新的 10.0 特性版都行）。必须是微软官方 SDK：Homebrew 等源码构建版缺 Brotli 静态库，编 Mac 版 C# 库会报 `_Brotli*` 未定义，doctor 会单独报这一条 | `compat/tree/global.json`；`tools/doctor.sh` |
| Python | 解释器 ≥ 3.12（doctor 判据；一键出包自己的下限是 3.11）。第三方包版本钉死：`capstone==5.0.7`、`lz4==4.4.5`，装在 `S2A_PY` 指的那个固定解释器里（环境变量或 `tools/machine.local`；没设用 PATH 上的 python3） | `tools/rewriter-requirements.txt`；`pack/oneclick/oneclick.sh` |
| bash | ≥ 5（Homebrew bash） | `tools/doctor.sh` |
| iPhone | 系统 iOS 18 或更新（产物编译下限 `IPHONEOS_DEPLOYMENT_TARGET=18.0`；完整游戏目前主要在 iOS 26 上验证，个别游戏打包时会提示需要 iOS 26）。当前完整验证仅覆盖 iPhone 17 Pro Max，其他机型请反馈运行情况。签名必须带「提高内存上限」权限：起局自检要整块 64 GB 地址窗口、可用内存 ≥ 4500 MB | `docs/内测教程.md`；issue #58 第 9 节；`runtime/src/selfcheck.c` |

Python 包缺了用一键准备建 venv 装齐（缺省本树 `build/venv`，同时装字体生成器与 App 运行环境的钉版依赖、准备 C 改写器固定依赖），再按它最后打印的那行设 `S2A_PY`：

```sh
python3 launchers/macos/prepare_build.py
export S2A_PY=$PWD/build/venv/bin/python3   # 或写进 tools/machine.local：S2A_PY=<同一路径>
```

## 2. 用自己的游戏出包

### 2.1 一键出包

```sh
bash pack/oneclick/oneclick.sh <源包文件夹> [--keys <prod.keys>] [--fonts <共享字体目录>] [--sysdata <系统数据目录>] \
     [--out <输出目录>] [--sign adhoc|dev] [--bundle-id <包名>] [--name <款>]
```

不带参数运行只打印上面这行用法（退出码 2）。

- **只想在 Mac 上起局**（第 1 步自查最常见）：加 `--target mac`，只出 Mac 能跑的私有产物根（按 macOS 出着色器函数库），跳过 iOS 编译和签名，快得多。
- **加 `S2A_WIDEN_AUTO_RUN=0`**：不然出包会等「宽屏自动出表」，那一步要占满本机的 Mac 局槽并起多局探测，外部贡献者用不到。
- **耗时**：首次刷新要编改写、着色器等，小游戏在 18 核 Mac 上实测约 40 分钟，之后同一款增量刷新快得多。主输出只显示「刷新进行中，已用 N 分」时，看 `<输出>/logs/refresh.log` 末行；若写着「出包暂停中（磁盘不足：可用 X G < Y G）」，是磁盘余量门槛挡住了，腾出空间后会自动继续。

- `<源包文件夹>`：一个游戏的 NSP / XCI，本体 + 更新 + DLC 放同一个文件夹（子目录 4 层以内都算）。本体必须恰好一款，32 位程序直接报红（S2Arm 只跑 AArch64，即 64 位 ARM 程序）。
- `--keys`：你自己的 `prod.keys`（密钥文件），缺省 `~/.switch/prod.keys`。只按路径交给解包工具，不复制、不打印。
- `--fonts`：共享字体目录。不给时依次找开发机原版字体目录、装着的 S2Arm.app 自带的开源替代字体；都没有就停，提示用 `python3 pack/fonts/make_open_fonts.py <目录>` 生成。
- `--sysdata`：从你自己主机固件解出的系统数据目录，见 2.2。
- `--out`：输出目录，缺省 `<源包文件夹>/s2arm_<款>`。
- `--sign`：`adhoc`（缺省，本机自签，不要开发者账号，给 AltStore / Sideloadly / Xcode 个人团队重签用）或 `dev`（开发直签，要签名团队号 `S2A_TEAM` 和对应包名的开发描述文件；团队号也可以写进 `tools/machine.local` 的 `S2A_TEAM_DEFAULT`，样例见 `tools/machine.local.example`）。
- `--bundle-id`：包名，缺省 `io.s2arm-exp.<款>`（`pack/ipa.sh` 私有产物根的缺省）。
- `--name`：款名，只许字母 / 数字 / `_` / `-`。缺省先查 `pack/oneclick/titles.tsv`，没登记的游戏用 `t<程序号小写>`。

出包分五步：认游戏 → 解包 → 私有产物根（播种 + 各阶段刷新：改写、系统数据、界面布局、追加内容、RomFS 索引、着色器预编）→ 编 App 签名打包 → 交付。任一步红就退出非 0，并打出停在哪一步、日志在哪。成功时最后一行是 `🟢 完成：…`，输出目录里有：

| 路径 | 是什么 |
|---|---|
| `<输出>/<款>.ipa` | App |
| `<输出>/<款>资源包/` | 游戏数据（资源包 v2：`manifest.json`、`index.tsv` 和按包内路径放的文件），要单独拷进 iPhone |
| `<输出>/roots/<款>@现行/` | 私有产物根（Mac 起局的输入，见 3.1） |
| `<输出>/logs/` | `unpack.log`、`seed.log`、`refresh.log`、`ipa.log`、`timing.tsv`（每步秒数）、`package.txt`（包号，回报要填） |

### 2.2 系统数据缺了怎么办

有的游戏会向系统要固件里的数据（例如 Mii 资源 `0100000000000802`、屏蔽词表 `0100000000000823`）。出包时 `pack/stage_sysdata.sh` 调 `pack/sysdata_need.py`，**每款都提供**，不按款判断要不要（10-25 起；原先按逐款手写的 `pack/sysdata_need.tsv` 判，漏登一款就起局 Break）：

- 产物根已有真数据 → 保留；`--sysdata` 目录里有 → 拷真的进包（产物根里是合成的也换成真的）；
- 都没有：Mii 资源 `0802`、屏蔽词表 `0823` → 自动合成一份「空但格式合法」的放进包（`pack/sysdata_synth.py`，几 KB，iOS / 安卓共用），不报红、不提示，游戏照常能玩：Mii 显示成空白，名字检查永远判不含屏蔽词。
  这是 10-25 维护者 拍板，覆盖原来「系统数据只认玩家目录、不造替代内容」在这两个号上的约束，原话：「我同意，能让玩家不要面对这个问题」。合成的只是最小合法结构，不含任天堂数据；
- 拿不到也合成不了的号（如 `0801` 错误信息文本）→ 不提供、不报红。起局后若游戏因缺数据退出，看 `host.log` 里的 `[S2A 系统数据] <号> 缺 OpenDataStorageByDataId` 行，按上面的目录结构放好你自己的系统数据，或给 `pack/sysdata_synth.py` 加合成器。
- `pack/sysdata_need.tsv` 只作统计（各款实际要了哪些号的普查记录），出包不读它。

系统数据是任天堂固件内容，不随仓库或 App 分发，S2Arm 也不提供获取方法。你已经有自己的系统数据时，按 `<你的系统数据目录>/<16 位号>/`（RomFS 文件直接在这层，号的大小写都认）放好，重跑一键出包并加 `--sysdata "<你的系统数据目录>"`（或设环境变量 `S2A_SYSDATA`）。

发现新游戏要的号，欢迎按 `pack/sysdata_need.tsv` 表头的列格式补一行（统计用）；能做「空但合法」合成的号，欢迎给 `pack/sysdata_synth.py` 加生成函数提 PR。

Android 资源包也复用同一核对表，入口为：

```sh
python3 android/tools/make_pack.py <安卓包输出目录> \
  --root <游戏产物根> --sysdata <你的系统数据目录>
```

`S2A_SYSDATA` 同样有效，显式 `--sysdata` 优先。预检在模块改写和替换旧包之前运行；
所需系统档案与产物根已有字体/时区在临时目录合并后进入 `systemdata/<号>/`，
逐文件写入资源索引和SHA-256，不修改输入目录。真实数据尚未提供时只会报缺，
不会生成空档案。合成夹具验证出包链，不代表对应游戏已通过验收。

## 3. 起局

单局约定：**每局 ≤ 300 秒**。依据：真机执行器 `tools/dev_run.sh` 测试段硬上限 `CAP=300`（只有个别重型款由调度放到 600）；Mac 健康表每局游戏 280 秒、含构建的墙钟上限 290 秒（`tools/mac_health.sh`）；宽屏闭环单局 295 秒（`graphics/widen/scan/closed_loop.sh`）。要更长先在 issue 里说明理由。

### 3.1 Mac 起局

缺省图形模式是**直连**：包里带本宿主口径的直连库就走直连（游戏的 NVN 图形调用直接翻成 Metal），否则退回**通用**（经 Ryujinx 显卡模拟层再到我们的 Metal 渲染器）。`host.log` 开头的「图形模式：」一行写明本局走了哪种、依据是什么。

```sh
S2A_CS=1 S2A_IN=<输出>/roots/<款>@现行 bash runtime/run_mac.sh <款> <局目录> 280
```

- **Mac 局要用按 Mac 目标出的包**：一键出包用 `--target mac`（它按 `S2A_PACK_PLAT=macos` 出），着色器函数库与管线归档按 macOS / 本机 GPU 架构出（`graphics/tools/shader_pack.sh` 用 `build/shbake/gpu_arch` 探测）。缺省是 iOS 目标（归档按 `applegpu_g18p` 出），拿它在 Mac 上跑会报【红】「管线归档与本机不匹配」、管线全部同步现编，首遇读数作废（#198 两份报告：同一路线现建单次 16.6–57.4 ms → 0.2–0.6 ms，132 条 → 50 条）。给 iPhone 出包不加。
- `S2A_CS=1`：构建宿主时把 C# 侧（服务层 + Ryujinx + 渲染器）链进去。Makefile 里它没有缺省值，不给就只链原生层，起局后进 C# 的系统调用全报未实现、读数作废。
- `S2A_IN`：产物根（只读）。里面有改写产物 `*.patched.bin` 就直接用；只有原版 `exefs/` 时在 `<局目录>/mods` 里现改写（单模块 ≤ 600 秒）。一键出包的私有产物根是前者。跑局期间别对同一款重新出包（出包会原地切换 `@现行`）。
- 脚本自己 `make host`，到秒数宿主自行优雅收局，退出码 0 = 正常收局；另有墙钟上限（秒数 + 30）和常驻内存上限（`S2A_MEM_MB`，缺省 16384 MB），超了杀进程、`host.log` 末尾记一行【红】。
- 局目录写 `host.log` 和 `frames.tsv`；Ryujinx 数据、着色器缓存、自动玩家输出都缺省放在局目录里（`S2A_RYU_DATA`、`NXGAL_SHADER_CACHE_DIR`、`S2A_AUTOPLAY_OUT`），几局并行不互踩。
- Mac 开发宿主缺省开「通用自动玩家」（自动导航进游戏、到可玩场景打 MARK），`S2A_AUTOPLAY=0` 关。

### 3.2 起局开关

下面的环境变量都在源码里核过读取处，Mac 局直接加在命令前，iPhone 局放进 `--environment-variables` 的 JSON（见 3.3）。

| 变量 | 取值 | 作用 | 读取处 |
|---|---|---|---|
| `S2A_GFX` | `direct` / `generic` | 本次图形模式。`direct` = 直连（游戏的 NVN 图形调用经直连 NVN 前端直接落到 Metal，不走显卡模拟）；看不懂的值打【红】按缺省（通用） | `runtime/src/gfxmode.c` |
| `S2A_SYSTEM_LANGUAGE` | Ryujinx 枚举名：`Japanese` `AmericanEnglish` `SimplifiedChinese` `TraditionalChinese` `French` `German` 等 | 系统语言；不给时跟设备首选语言。存档按什么语言存就给什么 | `services/S2A.Services/Host.cs` |
| `S2A_REGION` | `Japan` `USA` `Europe` `Australia` `China` `Korea` `Taiwan` | 地区，缺省 `USA`，不随语言变 | 同上 |
| `S2A_TIMEZONE` | IANA 名，如 `UTC`、`Asia/Shanghai` | 设备时区，不给跟宿主 | 同上 |
| `S2A_SYSTEM_TIME` | Unix 秒 | 游戏开机时的系统时间，之后照常走 | 同上 |
| `S2A_SAVE_DIR` | 目录（相对 = Documents 下） | 带存档起局：目录下 `device/`、`account/` | `tests/真机契约.md` 第 1 节 |
| `S2A_AUTOPLAY` | `1` / `0` | 自动玩家。iPhone 上缺省关，测试局必须给 `1` 才会有 MARK | `tests/autoplay/ap_default.h` |
| `S2A_VISION_BACKEND` | `claude` | 自动玩家看图兜底用你本机登录的 `claude` 命令行，不需要任何钥匙；不设时读 OpenRouter 钥匙，没有就关掉视觉兜底并报一行红 | `tests/autoplay/autoplay.c` |
| `S2A_RUN_ROOT` | 目录，缺省 `~/.s2arm/run` | 运行目录根：出包锁、存档、槽锁、成本账本、改写器依赖等都写在这下面。想和别的工作目录隔开就给一个自己的目录 | `pack/ipa.sh`、`pack/jobs/core.py` |

| `S2A_FRAMES_TSV` | 文件名 | 写逐帧表（Mac 由 `run_mac.sh` 设好；iPhone 给 `frames.tsv`） | `graphics/metal/cs/NxFrames.cs` |

截图开关：

- 直连录像 `S2A_DIRECT_REC=<起始帧>:<帧数>`（帧数 ≤ 4096，只在直连模式生效）：逐帧存 `rec/f_<帧号>.png`，每帧要等 GPU 写盘、帧率会降，功耗局不要开（`graphics/nvn/host_adapt.m`）。
- iPhone 整屏截图：`xcrun devicectl device capture screenshot --device <设备> --destination <文件>.png`（执行器同一条命令）。

**直连局的前提**：直连图形层从 `S2A_GAME_DATA/shaders/direct/` 读直连着色器库与映射表 `shader_map.tsv`（`graphics/nvn/host_adapt.m`）。这个目录由出包阶段 `pack/stage_direct.sh` 生成（`pack/refresh.sh` 在 `S2A_DUAL=1` 时跑，`pack/ipa.sh` 把它带进资源包）；一键出包对 `graphics/nvn/games/` 下有配置档的程序号自动设 `S2A_DUAL=1`（`pack/oneclick/oneclick.sh`），没有配置档的款 `stage_direct.sh` 报 🟡、不出库。零配置直连正按 方案_快速通用模式.md 推进；你的游戏想跑直连，先在 issue 里对齐。直连跑起来后，`host.log` 第一批行里应有「图形模式：直连（依据 环境变量 S2A_GFX=direct；…）」。

### 3.3 iPhone：手动装包起局

我们自己的测试设备走 `维护方工具 submit` 排队 → `tools/dev_run.sh <作业目录>` 执行（作业目录 = `job.env` + `*.ipa` + `pack/`；只认 `tools/devices.sh` 名单里的测试设备，日常手机一律拒绝）。外部贡献者有两条路：**① 推荐**：用同一个执行器跑自己的 iPhone，在 `job.env` 里写 `DEV=<你的设备名或 UDID>`，起执行器时加 `S2A_DEVICE_OWN=1`（`S2A_DEVICE_OWN=1 bash tools/dev_run.sh <作业目录>`）。它只在本机 `devicectl` 列出的已配对实体 iPhone 里找，恰好一台才用，起局、看门、拉回读数都和我们测试设备一样，局目录直接能给第 1 步的快检用；锁和电量文件放在 `S2A_OWN_DEV_ROOT`（缺省 `~/.s2arm/devices`）。**② 手动**：用下面的最小步骤，命令形状照搬 `tools/dev_run.sh` 实际用的 `devicectl` 调用。前提：包是 `--sign dev` 出的（`devicectl` 装包要开发签名），手机已信任这台 Mac 并打开开发者模式。

```sh
# 0. 找设备标识（下面的 <设备> 用 Identifier 或设备名都行）
xcrun devicectl list devices

# 1. 装包
xcrun devicectl device install app --device <设备> <输出>/<款>.ipa --timeout 600

# 2. 推资源包并在机上解开：只推机上没有 / 变了的文件，推完起一次 App 只解包、等解完（同启动器装机、dev_run、Windows 一键装机，一份规则 tools/push_pack.py）
bash tools/push_pack.sh <设备> <包名> <输出>/<款>资源包 --apply

# 3. 起局（环境变量是 JSON；这四个是执行器正式局的底子，按 3.2 往里加，例如 "S2A_GFX":"direct"）
xcrun devicectl device process launch --device <设备> --terminate-existing \
     --environment-variables '{"S2A_FRAMES_TSV":"frames.tsv","S2A_AUTOPLAY":"1","S2A_AP_SCENE":"1","S2A_AP_LOOP_S":"90"}' \
     --json-output launch.json <包名>

# 4. 到点收局（≤ 300 秒）：查进程号，再结束
xcrun devicectl device info processes --device <设备>
xcrun devicectl device process terminate --device <设备> --pid <进程号>

# 5. 拉回读数（每个文件一条；shots/、threads.txt、ap_summary.json 有就拉）
xcrun devicectl device copy from --device <设备> --domain-type appDataContainer --domain-identifier <包名> \
     --source Documents/host.log --destination <局目录>/host.log
xcrun devicectl device copy from --device <设备> --domain-type appDataContainer --domain-identifier <包名> \
     --source Documents/frames.tsv --destination <局目录>/frames.tsv
```

`<包名>` 是出包时的 `--bundle-id`（缺省 `io.s2arm-exp.<款>`）。经验（`tools/dev_run.sh` 注释记录的实测）：每条 `devicectl` 都带它自己的 `--timeout`，不要从外面杀正在传文件的 `devicectl`，否则下一局文件通道可能挂死、要重启手机。起局 30 秒 `host.log` 还空、60 秒没有「S2A 就绪」、60 秒没出帧、出帧后 10 秒不前进，执行器都判红停局，你手动跑也按这个口径判。

### 3.4 Android：一条命令起局出报告

前提：`bash android/doctor.sh` 过（JDK / SDK / adb 在位），`adb devices` 能看到你的设备并已授权。包用 `android/` 侧出的 APK（`android/test.sh`、Gradle 或一键出包），包名形如 `org.s2arm.game.t<TITLE>`。资源两种给法：`--resources <目录>`（已绑定 artifact 的资源目录）或 `--pack <make_pack 产物目录>`（现场绑资源再推）；纯 APK 试启动不加。

```sh
# 起局：取设备锁 → 记原安装状态（保证不了还原的直接拒跑）→ 装 → 冷启动 → 等 READY
#   → 按秒数采 logcat/逐帧/电池/截图 → 收局（确认游戏与采集进程都停了）→ 逐项还原并验证。
python3 android/tools/run_game.py --apk game.apk --package org.s2arm.game.t0123456789ABCDEF \
    --serial <adb devices 里的序列号> --out runs/game/out_1 --seconds 60 \
    [--resources <目录> | --pack <目录>] [--mode direct] [--extra s2arm.KEY[=VALUE] ...] \
    [--discharge-settle 30] [--discharge-timeout 300] [--power-interval 1.0] \
    [--no-power-sampler [原因]] [--checkpoint <检查点目录>] [--allow-data-loss]

# 判读：局目录直接给第 1 步的快检用
python3 tools/quality_check.py runs/game/out_1
```

- **设备锁**：同一台设备同一时刻只有一个局。锁文件放持久目录 `<锁根>/<serial>/`（`--lock-root` > `S2A_ANDROID_LOCK_ROOT` > `$S2A_RUN_ROOT/android-devices`，缺省 `~/.s2arm/run/android-devices`；不放 /tmp），`device.lock` 是内核文件锁（`tools/flock_hold.py` 持锁小进程盯着持有者 PID）、`holder.json` 记持有者 / 开始时间 / 进程号 / 持锁令牌。手动用：`python3 android/tools/device_lock.py acquire|release|status|clear --serial S`（`release` 要 `acquire` 打出的 `--token`，令牌不符拒放，防止别的会话顺手清场）。
- **留置（不放行）**：上一局**未正常结束**——进程崩溃 / 被强杀 / adb 掉线导致锁丢而 `holder.json` 还在——下一手 `acquire` 判「设备状态未证」落下 `detained.json` 并返回 3，**不自动放行**；取锁中途等到的留置标同样算数。唯一放行路：人工核查设备后 `device_lock.py clear --serial S`。
- **还原范围与拒跑**：保证不了还原的一律拒跑不兜底——① 设备已装该包：是 debuggable 就装新包前 tar 把 `/data/data/<pkg>`、`/sdcard/Android/data|obb/<pkg>` 流式拉回 `--backup-dir`（默认 `<out>/data-backup`，tar + `manifest.json` 全量清单：文件 sha/软链目标/目录含空目录/权限位）。访问通道按目录归属：**私有树 `run-as`（应用 uid 才够权），外部目录走 shell**（9000 实测 `run-as` 碰 `/sdcard/Android/*` 被 SELinux 拒，shell 有外部存储全权）——探测/清单/tar/回灌命令本体不变；exec-out 流分块落盘边算 sha256 不整进宿主内存（9000 私有树 ~7.3GB，`capture_output` 会爆；`tar_entries` 核对同样分块读成员）。归档先在宿主机解包与源清单逐项核对、对不上拒跑；收局装回原包后归档复核过才 `pm clear`、回灌、设备端同口径复核；设备端目录清单三件套（文件 sha / stat 类型权限 / 软链目标）走 `find -print0 | xargs -0 -n 256` 分批——`-exec {} +` 把全部路径摊进一次 exec，4 万文件私有树撞 toybox E2BIG（9000 实测，与 deploy 资源核验同病同治）；清单命令包在 `cd dir && { set -o pipefail; … }` 组里，收尾凭据四项——`S2A_FRC`（find 自报 rc，xargs rc=0 吞不了上游 find 失败）、`S2A_RC`（管道 rc）、`S2A_N`+`S2A_CRC`（独立 find 计数与其管道 rc）、`S2A_ERR:` 前缀逐行回投设备 stderr（adb 会把设备 stderr 混进 stdout，靠宿主侧 stderr 判不了；白名单现为空，有 stderr 即未证）——任一 rc 非零/缺失、计数非数字、解析条目数≠计数、stderr 非白名单，一律「清单未证/不完整」拒，半截不当全量；计数先行、`n=0` 不跑 `find|xargs`（toybox xargs 无 `-r` 默认空输入也跑一次命令，幻影行会让纯空树误拒）；stat 清单 `find . -mindepth 0` 含根目录自身，与归档 `./` 根成员同口径对拍根权限；坏值（空/非数字计数、非八进制 mode）是受控「未证」失败，进 fails → manifest + 留置，不逸出；备份 tar 的 stderr/rc 同病同治——`exec-out` 会把设备 tar stderr 混进归档字节流、宿主 stderr 是空的，设备侧落**树外**凭据 `/data/local/tmp/s2a-tar-<tag>-<uuid>-{err,rc}`——放被备份树里会开头 `rm -f` 删到用户同名文件、固定名撞并发（qa-fone #329620）；shell 预建 0666（run-as uid 也能 2>/> 写）、`[ ! -e ]` 先证不存在（存在即停不覆盖），tar 不再带 --exclude；凭据创建即登记待清，流超时/写盘失败/任何异常出口都先 rm+test ! -e 核删（qa-fone #329632），拉完 cat 取证——rc≠0/stderr 非白名单/读不回/删不净 = 「备份未证」拒跑；备份中途失败视为还原链未证 → 收局并入 fails 留置，不得正常放锁；目录三态探针——存在但进不去报错拒跑，不当不存在。不是 debuggable 则拒跑，显式 `--allow-data-loss` 才放行且只还原 APK 字节（`restore_scope` 写明）。② 分包（split APK）安装的设备：装回不可靠，直接拒。③ 原本没装：收局卸载并复核 `pm path` 已清、`/sdcard/Android/data|obb/<pkg>` 无残留（存在但读不进也算没证清，留置）；原本装了别的构建：`adb pull` 备份原包、收局 `install -r` 装回并 sha256 复核；原包 versionCode 低于新包时装回是降级——入局前证不了能装回（同版 `install -r -d` 不触发版本排序，证不了真降级；先升级入局、收局再试 = 装了赌能降回去），所以连拉包、装包都不做直接拒跑，设备原样（qa-fone #323273 裁定）；原包高于新包时装测试包本身即真降级，`install -r -d` 失败直接拒跑（装失败不卸旧包）。
- **检查点预置**（`--checkpoint <目录>`，`s2a-checkpoint/1`：`meta.json` + `saves.tar` + `saves.tar.sha256`）：只收原未安装的局——设备已装该包直接拒跑（解入会清/盖已有数据，连安装步都不进）。装包与资源部署之后、首次 `am start` 之前，宿主先核——schema/包名 与本局一致、`title_id` 是规范 16 位大写十六进制、`meta.files` 每项是 `[长度, sha256]` 对（JSON 重复键、非 64-hex 都拒）、`saves.tar` sha256 与 `.sha256` 相符、tar 成员只收普通文件与目录（绝对路径 / `..` 段 / 软链硬链 / 设备节点 / 重复成员名一律拒）、tar 成员与 `meta.files` **严格一致**（多出/缺漏/声明长度与成员长度不符都拒）——全过才 `adb push` 到 `/data/local/tmp`，`run-as` 解进 BootSpec 冻结的存档根 `files/user/0/saves/<titleId>/ryujinx-android`（`S2A_SAVE_DIR` 在安卓 typed BootSpec 下不生效，存档在其 `bis/user|system/save` 下；`prepareState` 只许 `ryujinx-android` 一个布局项，检查点 tar 必须以 `bis/` 为根），再按 `meta.files` 逐文件 sha256 复核。**任一门不过 → Refuse 不起局**，manifest `checkpoint` 记 `verify=fail` 与原因；逐文件复核不过时设备端原始清单（`stat -c %a|%F|%n` / `sha256sum` / 软链表）落 `out/checkpoint-device/` 供归因，manifest 记 `device_listing`；过门记 `verify=ok` + 检查点名/scene/titleId/源 tar sha256/文件数。临时 tar 删除失败记 `checkpoint.tmp_left` 并入收局还原失败 → RESULT=red + 留置。检查点写入的数据属本局产物，收局还原链照旧（未安装起步随卸载清掉）。
- **收局与中断**：任何结果——SIGTERM / SIGHUP / Ctrl+C / 未捕获异常——都走 finally 还原；先把游戏进程收掉（优雅 `s2arm.finish` → force-stop 兜底）并确认游戏与 logcat 采集进程都停了，再逐项验还原。SIGKILL / 宿主断电走不到 finally = 未正常收局，按上面留置规则处理。调试属性 `debug.s2a.*` 起局前置 1、收局恢复原值并逐项读回核对（release 构建不让改只记注，不误判红）。**任一项还原失败：RESULT=red + 留置标，退出码 3。**
- **READY**：等 logcat 里 `Game startup accepted:`（`--ready-timeout`，缺省 180 s）；`am start` 输出带 Error/Exception、进程中途退出或超时都直接红。
- **产出**：`android.json`（包名 / 机型 / SoC / 安卓版本 / 启动命令 / 帧窗口 / 当局进程绑定）、`shots_ap/`（起止整屏截图）、`frames.tsv`（`frame/present_ns/present_us/wall_us/disp_us/disp_seq`——**只写采集窗口内的 direct-present 帧**：帧记录是 CLOCK_BOOTTIME，窗口边界取设备 `/proc/uptime` 同一时钟裁；帧日志块先按 logcat 行 PID 圈当局进程、再按 meta `uuid=` 硬绑本局（与私有文件同一 `debug.s2a.session_uuid` 锚，缺/不符整段不收），别的进程的块不进表。present_us/wall_us = 宿主算的相邻 present 间隔（CPU 口径）；disp_us/disp_seq = v5 记录里 displayTiming 已确认的真实上屏间隔与其所属帧号，按 seq 对号写、未确认/旧版记录留空——不是 SurfaceFlinger 合成时序。解析与 p50/p95/p99/1%low 见 `frame_log.txt`）、`power.tsv`（`t + tools/android_power.py 的 FIELDS + level`：boot_us / status / current_ua / voltage_uv / charge_uah / 四路供电旗标 / plugged / interactive / power_save / thermal_status / source 等原样落盘，未知态不坍缩成未接电）、`logcat.txt`（整窗 threadtime）、`battery.txt` / `thermal.txt`（收局时 dumpsys 快照）、`gfx_mode.txt`（按 logcat 认直连 / 通用）、`run-manifest.json`（原安装状态 / 还原范围 / 失败原因 / 注记）、`host_logs/`（收局后、还原清私有目录前 run-as 拉回的当局私有证据：`host-*-<pid>-*.log` 宿主日志原始字节 + `frame-log-<pid>.log` native 直写帧日志——与 logcat 转储同文双写，logcat 分片被截断时它是完整源，归并进帧块解析；非 debuggable 包 run-as 进不去就只记注不拉；归属判定 fail closed——bound 要求文件内容自述本局 `session_uuid`（运行器起局前 setprop `debug.s2a.session_uuid`，os.c 会话日志首行 / 帧日志 meta 行尾都写），字段缺、值不符、PID/birth/stat/墙钟任一证不了 → `session=unproven` 照收记账）。debug 门只在调试构建 + `debug.s2a.debug_env=1` 下出帧日志，正式构建或非直连 provider `frames.tsv` 只有表头、帧率判「没数据」是预期。
- **电池采样走设备侧守护**：起局后 `setsid` 后台 mksh 循环每秒把采样块写进 `/data/local/tmp/s2a-power-samples.log`（`===` 分块、应用无关的私存文件；守护自写 `.pid`、循环埋 `s2a-power-sampler` 标记），宿主按 `--power-interval` 拉回——adb 中途掉线只断拉取、不断设备上的采样；spawn 回执必须是一个数字 PID（空回/半截回执 = 未证，按起失败处理照扫孤儿，启动中断也扫）；收局 / 中断 / 起守护失败都按已知 PID + `.pid` 文件 + `pgrep -f` 标记三路扫干净（`>log 2>&1 </dev/null` 全 fd 脱离 + `setsid` 另开会话，adbd 立即放回），kill 前先按 `/proc/<pid>/cmdline` 核标记防 PID 回收误杀，杀后等 `/proc/<pid>` 没了才清文件——杀不掉的回 LINGER 留证报错（日志照拉回、设备文件不清），收局路径并入还原失败留置。判读能耗要先**物理拔电**（不能 `dumpsys battery set` 模拟），再经放电稳定门：尾部一串「连续物理放电」采样满 `--discharge-settle` 秒（缺省 30）才进采集窗，`--discharge-timeout`（缺省 300 s，0=不限）等不到就照常采集并在 manifest `power_sampler` 记 `settle_ok=false`；未显式给 `--discharge-settle` 且最新采样证在接电/充电时门判不适用直接进窗（`settle_na` 记明原因）——守护刚起首块未落盘是常态，首读为空先补拉三轮、仍无样本就用同口径 dumpsys 现态判接电，不许把接电局拖进放电等待；显式给了照等。接电功能局 / 帧时性能局不需要能耗数据可给 `--no-power-sampler [原因]`——守护干脆不起（也就没有孤儿），`run-manifest.json` 记 `power_sampler.disabled` + 原因，`power.tsv` 不落，quality_check 能耗报「没数据」读数写明未开采样。
- **能耗口径**（兄弟项目 power-comparison 同式）：`run_game.power_battery_window` 的块边界 = `frame_window_us`，分析窗剔首 15 s / 尾 5 s；窗内每个采样点都要物理放电（`status=Discharging` 且 `plugged=0`——四路供电旗标全证 false 才合得出）、屏幕交互、非省电、`thermal_status<3`、电流/电压/电量计读数合法、电流符号一致、采样间隔 ≤3 s、边界全覆盖——**充电 / 接电旗标 / 掉线空洞 / 状态翻转任一条整块作废**；积分取 `abs(current)×voltage` 梯形（原始符号记 `rawCurrentSign`），窗内再用电量计斜率比值门（0.5–1.5）。`quality_check.py` 再对整局跑 `power_charge_corroboration` 交叉核对（电量计等差递减推量子 q → 端点差 ±q 区间收电流积分；否则整局比值门，向下跳变 <2 次不成立）——互证过才记「未证」（电池侧估计、未经外部表计校准、不套 iPhone 门槛），不互证连「未证」都不给、直接「没数据」并写明哪一个门拦的。
- **边界**：只经 adb 做 安装 / 启动 / 采集 / 截图；不重启、不刷机、不 root、不改系统设置。
- **限制**：安卓没有自动巡线 MARK（`android.json mark=0`，整窗计开局）；`<300s` 窗口内省电 / 锁帧策略可能与长局不同；本工具只在宿主测过 adb 替身，真机冒烟与判读口径由维护者分批验收。

### 4.2 frames.tsv 列含义

由渲染器每上屏一帧写一行（`graphics/metal/cs/NxFrames.cs`，表头写死在 `Head` 常量里），制表符分隔，首行列名。第 1 行（`frame` = 1、`wall_us` = 0）是启动以来的累计，判据都不算它。契约见 `tests/真机契约.md` 第 3 节。

| 列 | 单位 | 含义 |
|---|---|---|
| `frame` | — | 上屏序号，从 1 起 |
| `wall_us` | 微秒 | 与上一帧上屏的间隔 |
| `alloc_b` | 字节 | 本帧全进程托管分配（`GC.GetTotalAllocatedBytes` 差分） |
| `gc0` `gc1` `gc2` | 次 | 各代 GC 累计次数 |
| `rb_us` | 微秒 | 本帧 CPU 等 GPU 读回的阻塞 |
| `draw_n` `pass_n` `upload_n` `rw_kb` | 次 / 次 / 次 / KB | 本帧绘制数、渲染遍数、上传数、附件读写量 |
| `shader_miss` | 次 | 本帧离线着色器库没命中、当场翻译的着色器数 |
| `alloc_gpu_b` | 字节 | 编码线程（渲染器上屏那条线程）本帧托管分配；不是 Ryujinx 的 GPU 命令线程 |
| `disp_us` | 微秒 | 画面真正上屏的间隔；帧率格优先用它，没有就退回 `wall_us` |
| `macro_n` `macro_interp_n` `macro_us` `macro_interp_us` | 次 / 次 / 微秒 / 微秒 | 本帧显卡宏执行次数、其中走解释器的次数、总耗时、解释器耗时 |
| `xlate_n` | 次 | 本帧 Ryujinx 当场翻译的程序数（着色器包没覆盖到的） |
| `pso_n` `pso_us` | 次 / 微秒 | 本帧现建管线（归档没命中）个数与耗时 |
| `cam_x` … `cam_pitch`（8 列） | — | 宽屏包装层登记的镜头位置、前向、偏航、俯仰；本帧没有透视主镜头时为空 |
| `gpuq_us` | 微秒 | 本帧编码线程等命令分配器环的时长（GPU 跟不上的反压） |
| `gc_pause_us` | 微秒 | 本帧 GC 停顿增量；首帧为 0 |
| `alt` | — | 同局交替开关的相位 + 1（0 不交替、1 关段、2 开段） |

### 4.3 功耗怎么取

**iPhone 整机功率**（判据用这个）：在 MARK 那一刻（`pwh.plist`）和结束 App 之后（`pw1.plist`）各采一次电池的 IORegistry（起局前另采一次 `pw0.plist` 作基线，`tools/dev_run.sh`），取两次之间 `AccumulatedSystemLoad` 的差 ÷ `SystemLoadAccumulatorCount` 的差 ÷ 1000，单位瓦。这是整机耗电，不管电来自电池还是充电器；不用 `AccumulatedSystemEnergyConsumed`（充电时会把充电功率算进去）。执行器用的命令（`tools/dev_run.sh`，要 Homebrew 的 `libimobiledevice`）：

```sh
idevicediagnostics -u <UDID> ioregentry AppleSmartBattery > <局目录>/pwh.plist   # host.log 出现 MARK 时
idevicediagnostics -u <UDID> ioregentry AppleSmartBattery > <局目录>/pw1.plist   # 结束 App 之后
python3 -c "import sys; sys.path.insert(0,'tools'); from score_cells import window_power; print(window_power(sys.argv[1]))" <局目录>
```

最后一行打印瓦数（读不到打 `None`）。读数旁边记下充电状态和 `[电]` 行。

**进程自己的耗能拆账**：`host.log` 每 10 秒一行 `[能耗]`（4.1），按线程看谁耗电；iOS 上 GPU 一栏取不到。仓库里没有用 `powermetrics` 的脚本。

### 4.4 离线判据脚本（都只读）

```sh
python3 tools/game_fps.py <局目录>         # 游戏要的帧率：「30<TAB>游戏请求交换间隔 2（30 帧/秒）」；取不到退出 1
python3 tools/frame_gate.py <局目录>       # 分配闸门：绿|红|未测 + 说明；退出码 0 / 1 / 2
python3 tools/firstuse_scan.py <局目录>    # 首遇合计：「0<TAB>现建管线 0、程序编译中跳过绘制 0、特化慢 0」
python3 tools/score_cells.py <局目录> --game=<款> --commit=<包提交> --diag=1   # 记分板各格（能玩 / 画面 / 帧率 / 能耗 / 首局 / 分配）只打印、不写记分板
```

首局格任一到 MARK 的局都判，不分冷热、不用配热局（10-24 起；`score_cells.py` 已不认 `--cold` / `--warm`，见 6.5）。

### 5.2a 一条命令自查：移植质量快检报告（可直接贴 issue、可入能力卡）

跑完一局（Mac 局目录或 iPhone 局目录都行）后，一条命令出五项结论（画面 / 帧率 / 满屏 / 直连默认启动 / 能耗，各写「过 / 不过 / 没数据」）：

```sh
export OPENROUTER_API_KEY=<你自己的钥匙>   # 或 ANTHROPIC_API_KEY；都没有时装好 claude 命令行也行（用你自己的 Claude 看图）
python3 tools/quality_check.py <局目录> --report <报告目录> --game <款> --device <机型> --contributor <署名> [--root <产物根>]
```

- 局目录要有的文件（都放顶层）：`host.log`（必须，身份 / 帧节拍 / MARK / 出图层比都从这里读）、`frames.tsv`（帧率）、`shots_ap/ap_*.png`（iPhone 手动局从 App 的 `Documents/` 根下拉 `ap_*.png`；Mac 局截图在局目录顶层 `ap_*.png` 与 `vision/`，不用挪）；可选 `pwh.plist` / `pw1.plist`（iPhone：到游戏画面时、收局后各采一次 `idevicediagnostics -u <设备> ioregentry AppleSmartBattery > pwh.plist`，不采则能耗记没数据）。`gfx_mode.txt` 不用拉（执行器才写，快检自己读 host.log）。
- 输出 `<报告目录>/report.md`（整段贴进 issue）、`report.json`（机器可读，带工具指纹、每份证据的 sha256、程序号 / 构建号）、`evidence/`（截图、`frames.tsv`、`gfx_mode.txt`、功耗采样、`host.log`）。

维护方入账（贡献者也可以自己跑 `verify` 先看能不能入）：

```sh
python3 tools/caps_ledger.py verify <报告目录>   # 复算证据 sha256 与报告指纹
python3 tools/caps_ledger.py ingest <报告目录>   # 写 docs/名单_验证账.tsv：工具生成、原件齐、指纹可复算 → 贡献者验证
```

## 6. 各类任务的验收口径

每类写「要证明什么 → 怎么测 → 判据 → 回报贴什么」。判据数字都取自仓库现有闸门，括号里是出处；改判据请改出处文件，不要在 PR 里另立口径。通用要求：同一结论至少两局；读数旁写清局数、帧数（射程）；没测的明说没测。

### 6.1 正确性（能玩）

- **要证明什么**：游戏能进可玩场景、不崩、不报红、有声音。
- **怎么测**：Mac 通用局或 iPhone 局各一局，带 `S2A_AUTOPLAY=1`（iPhone）；有存档就带存档。
- **判据**（`tools/score_cells.py` 能玩格）：有 `S2A 标记 MARK`；没有 `CRASH`；报红 0（按 `tools/redline.py` 口径，空的「未实现服务：」汇总行和「出图未满屏」不算）；`[声] 稳态窗口：输出峰值` > 0。画面格另要有「[画] 满屏判据 已开」、没有「【红】出图未满屏」。
- **回报贴什么**：MARK 行、报红行全文（去重计数）、声音峰值行、`score_cells.py --diag=1` 的能玩 / 画面两行、一张可玩场景截图。

### 6.2 帧率

- **要证明什么**：游戏按它自己要的帧率稳定跑。
- **怎么测**：iPhone 正式口径局（`S2A_AP_SCENE=1`，MARK 后采满 60 秒），不要给帧率封顶的开关（`S2A_FPS`）。
- **判据**（`tools/score_cells.py` 帧率格）：MARK 后窗口 ≥ 55 秒墙钟；平均帧率 ≥ 游戏要的帧率（`帧节拍` 最后一行）× 99%；慢帧（> 1.5 倍帧预算）≤ 1%。取不到帧节拍行、帧率被封顶 = 局无效。
- **回报贴什么**：`game_fps.py` 输出；帧率格那一行（平均、中位、慢帧百分比、帧数）；两局以上的读数。

### 6.3 能耗

- **要证明什么**：整机功率达标，或某个改动确实省电。
- **怎么测**：iPhone 正式口径局，按 4.3 采两次功率。比较改动用同包 A/B：A 局不带开关、B 局带开关，同机同存档同场景；A/B 局用 `S2A_AP_SCENE=2`（静置）噪声最低。
- **判据**：能耗格：窗口整机功率 ≤ 门槛——游戏要 60 帧（帧节拍 ≥ 59）≤ 4.8 W，其余 ≤ 3.7 W（`tools/score_cells.py` 的 `W_MAX60` / `W_MAX`），且同局帧率格绿（降频省电但掉了帧不算，`tools/score_cells.py`）。A/B：先跑同包 A/A ≥ 3 局（非充电优先）取极差作噪声底，B − A 的绝对值超过噪声底才算有差别；没有噪声底就不判功耗，不借别的游戏的数（`tools/ab_noise.tsv` 表头、`tests/真机契约.md` 第 5b 节）。
- **回报贴什么**：每局瓦数 + 充电状态 + 热状态（`[gal] 热状态` 行，如有）；A/A 极差；B − A；同局帧率格。

### 6.4 分配

- **要证明什么**：玩的时候不因为垃圾回收卡顿。
- **怎么测**：任意带 `frames.tsv` 的局（Mac 或 iPhone），MARK 后满 60 秒；查原因时加 `S2A_ALLOC_TRACE=1` 看拆账（诊断局，读数不作验收）。
- **判据**（`tools/frame_gate.py`，`tests/真机契约.md` 第 5 节），任一条超即红：① 窗口每帧分配均值 ≤ 2048 B（60 帧游戏）/ 4096 B（30 帧游戏）；② 整局（第 1 帧到收局）单帧 `gc_pause_us` 最大值 ≤ 帧预算 25%（30 帧 8.3 ms / 60 帧 4.2 ms）；gen2 那一帧在游玩中照判，读盘 / 黑屏中单列记录不判；③ 窗口内 `rb_us` 合计 ≤ 窗口墙钟 1%，单帧 `rb_us` ≤ 1 帧预算。缺 `alloc_b` / `gc0` / `gc1` / `rb_us` 任一列 = 未测。
- **回报贴什么**：`frame_gate.py` 整行输出（它已带窗口帧数、均值、最长停顿与帧号）；超限那几帧对应的 `[gc]` 行。

### 6.5 首遇卡顿

- **要证明什么**：玩家第一次玩不为着色器 / 管线首遇付费。
- **怎么测**：任一局（不分冷热，10-24 维护者「不管凉机还是热机，过了就行」）跑到 MARK 即可，不用配同包热局。
- **判据**（`tools/score_cells.py` 首局格）：起局到收局 > 100 ms 的帧里，**我方开销**造成的 = 0（当帧宏耗时 `macro_us` ≥ 帧时 70%，或当帧有当场翻译 `xlate_n` / 现建管线 `pso_n` / 现翻着色器 `shader_miss`）；游戏自己读盘的「游戏加载停顿」只记读数、不判；`shader_miss` 合计 = 0；`pso_n` 合计 = 0；「【首遇】管线特化慢」行 = 0。没有 `shader_miss` 列 = 未测。
- **回报贴什么**：`score_cells.py <局目录> --game=<款> --commit=<包提交> --diag=1` 的首局行（带「>100 ms 我方 N 帧（帧号…）、游戏加载停顿 M」）；剩下的我方 > 100 ms 帧号与附近的「管线现建 / 着色器首遇现编」行。

### 6.6 宽屏

- **要证明什么**：你的游戏在宽屏下画面满宽、比例对、不露空、界面不被多切。
- **怎么测**：宽屏点集由 `graphics/widen/scan/auto_table.sh <款>`（出包发现没有表时自动在后台起）或 `graphics/widen/scan/closed_loop.sh <款> <局目录> <点集> <录像帧 a-b>` 闭环验证；档位 `S2A_LOOP_MODE=docked|handheld` 必给，屏幕宽 `S2A_SCREEN_W`（缺省 2346）。
- **判据**（`graphics/widen/scan/closed_loop.sh` 头注释，全过才写表）：0 崩、到 MARK；点集里每个点都执行到；出图源宽高比 = 屏幕比（±0.01）；3D 镜头比 = 屏幕比（`tests/visual/proj_aspect.py` 退出码 0）；露空 ≤ 0.5%（`tests/visual/widen_holes.py`）；有界面拷屏点时再走界面路线：路线走到 END、拷屏贴回 ≥ 1 次且 0 红、中间 16:9 区整列纯黑 0 列、界面裁剪多切的像素 ≤ 对照局 × 1.5 + 2000。都不过 = 不写表，照旧 16:9 原比例居中留黑边（这不是红：`出图原比例居中` 行）。
- **回报贴什么**：闭环脚本的判据读数行（它写进 `来源.txt` 的那行）、档位、屏幕宽、两张截图（16:9 对照与宽屏）。

### 6.7 直连

- **要证明什么**：直连模式下游戏能跑、不崩，帧率不退、功耗比通用低。
- **怎么测**：同包两局：`S2A_GFX=generic` 与 `S2A_GFX=direct`，其余条件相同；直连局额外录 20 秒有动作的连续画面（`S2A_DIRECT_REC=<MARK 后某帧>:<帧数>`，录像局不作功耗读数）。前提见 3.2「直连局的前提」。
- **判据**：`host.log` 有「图形模式：直连」；0 崩、报红 0、到 MARK；帧率格判据同 6.2；功耗对比按 6.3 的 A/B 噪声底口径。画面不做逐帧对拍门禁，靠录像人看（`docs/设计_直连架构.md` 第 0 节第 4 条）。
- **回报贴什么**：两局的图形模式行、报红数、帧率格行、瓦数与噪声底；20 秒录像（`rec/` 合成的视频）；直连跑不起来时贴「直连：…」开头的【红】行和最后 50 行 `host.log`。

## 已知约束与坑

下面是 #266 实走（8 款自有游戏 × Mac，源码 `2b52457e0`）实测到的、会直接让出包 / 起局失败的用法约束。都是环境与调用方式问题，不是代码缺陷；遇到时按这里改，不要去改对应源码。

- **产物根（`--out`）必须落在仓库外。** 走零配置推导的款（仓库里没有手写配置档 `graphics/nvn/games/<程序号>/game.tsv`）会进 `graphics/nvn/tools/direct_profile.py` 的 `validate_output()`，它把 `NX.parents[1]`（= 仓库根）与 `root/exefs`、`root/romfs`、`root/aoc` 一起当输入根：产物根建在仓库里 → `【红】直连配置阶段拒绝：output must be outside source/input root`（`direct_profile rc=1`），这次降级成只出通用。做法：`S2A_ROOTS` / `--out` 指到仓库外（例如 `~/.s2arm/out/<任务>/<款>/roots`），实测同一份输入 `rc=1` → `rc=0`。详见 研究/直连实走_s-leeq「--out 必须落在仓库外」。
- **`S2A_WIDEN_AUTO_RUN=0`。** 缺省值 1 时，`pack/ipa.sh` 会等宽屏自动出表 —— 那一步会占满 4 个 Mac 局槽并等满 5400 秒；实测出包被它卡死。只要这次不专门出宽屏表，就显式关掉（出包 + 跑局两条链都要带）。
- **`S2A_MEM_MB=8192`。** 缺省 16384 时与并行出包抢内存账，Mac 局拿不到槽（`维护方工具` 先等槽、再按这个值预留内存）。并行出包或同时要跑局时显式调小。
- **私有根的包名不能走开发直签。** 私有产物根的包名 `io.s2arm-exp.<款>` 在 Apple 侧不可注册（申请描述文件失败），出包要加 `--sign adhoc` 自签；只跑 Mac 局时用产物根即可，不必出 ipa。
- **固定 Xcode 路径是旧版约束。** #266 的基线 `2b52457e0` 曾按 `tools/toolchain.env` 中的 `/Applications/Xcode-27.1.app/...` 取工具链，缺这个路径会报红。当前 `pack/refresh.sh`、`pack/ipa.sh` 和 `make host` 已改用本机工具链选择，不再需要为旧路径创建同名软链；出包入口的选择顺序见 1.2。`make host` 还会沿用环境中已有的 `DEVELOPER_DIR`；需统一指定时设置 `S2A_DEVELOPER_DIR`。`tools/toolchain.env` 中仍保留历史路径值，但这些入口不把它作为缺省 Xcode。
- **默认 iOS-only 出包，Mac 侧少一个 `_b.metal` 就整包判红。** `S2A_PACK_PLAT` 不是 `macos` 时 `pack/stage_direct.sh` 传 `--no-mac-lib`（Mac 侧不编 metallib），而 `graphics/tools/direct/lib_swap.py` 仍要求「出成的键在 Mac 侧 `_b.metal` / `_b.json` 成对」。八方旅人 II 的 13980 个键里有 1 个出不成 → `🔴 Mac 侧 _b.json 13980 个、_b.metal 13979 个，对不上` → 整包不出直连库。要跑 Mac 局就显式 `S2A_PACK_PLAT=macos`（Mac + iOS 两份都出）；实测同一份输入改这个开关后 `rc=0`。
- **`timeout` 用仓库自带的 perl 版，不需要装 coreutils。** `tools/bin/timeout` 是正式实现（先 TERM 整组、宽限后按整棵子孙树 KILL、124、信号转发）；脚本头加载 `tools/_timeout.sh` 就无条件把 `tools/bin` 放到 `PATH` 最前，规则只写在那一个文件里（`tools/toolchain.sh` 也 source 它）。macOS 默认没有 GNU `timeout` 不再影响出包 / 门禁 / 自检，`exec timeout …` 照用（`PATH` 上是外部文件）。不用 GNU 版的原因：它自立进程组，嵌套时外层按组杀不到内层——出包撞 nchain 2 小时上限后 `direct_lib` 成孤儿、续写盘 2 小时；perl 版留在调用方组里、收信号转给子组。单测 `bash tests/timeout_shim_test.sh`（6 秒）：干净 `PATH` 下断言 `command -v timeout` 指向 `tools/bin/timeout`，124 / 0 / 退出码原样 / `exec` 可用 / 子孙一个不剩，并拿 `services/romfs_index.sh` 当真实入口（main 上 127、本树 0）。

### Android 冷启动主机模式

游戏 APK 的启动 Intent 可显式传 `--es s2arm.console_mode handheld` 或 `--es s2arm.console_mode docked`；缺失保持 handheld。只允许这两个原值，错误类型、空值、大小写或空白差异均拒绝。已有进程的 singleTop Intent 不能切模式；先按正常收尾流程退出，再启动下一局。此入口不持久化、不新增玩家设置页面。

Activity 在 surface 准入时生成不可变 FrozenStart，HostApi 注册、审计 BootSpec JSON 与 native 启动整数都来自它。记录 APK SHA、同次 PID/birth/session 和 BootSpec，再核 HLE 实际运行模式；仅发了 Intent 或见到 HostApi 字样不足以证明 guest 已切换。运行模式、正常1x与实际操作窗帧率分别验收；9000使用handheld，8E使用docked。默认handheld的旧局不能归为docked结果。

本接缝的纯 Java 正控71项、四份源码负控已由独立审查在实际JDK17重编运行；Activity/JNI/HLE与设备模式仍须Android构建和实际冷启动验证，不由JVM检查替代。

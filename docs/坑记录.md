# 坑记录

## 同一提交内从缓冲复制到贴图可能读回旧字节

- 现象：计算着色器先更新缓冲，后续缓冲到贴图的拷贝使用带填充的行距。提交完成后，生产者首字为 0x24240000，目标 mip 1、layer 1 的 2×2 子区仍为旧值 0x35353535。
- 根因：GPU 的新数据在池镜像中，完成回调才写回客体内存。拷贝若提前从客体地址取字节，再把它们上传到贴图，就会复制旧版本。
- 实验：基线 f0c7ae8cf，Mesa 26.0.8、VVL 1.4.341、同步校验开启。GPU 源臂目标 4 个像素从 4 错变为 0 错；纯 CPU 源臂始终 0/4 错，两臂各 156 个区域外或相邻子资源像素始终 0 错。
- 做法：源区间与待落地 GPU 写相交时，普通格式在命令缓冲内从池镜像复制；需要 CPU 转换的待落地区间报出原因。CPU 源保留原上传入口。验证时同时读取生产者、目标子区和相邻子资源。
